# realtime-task-scheduler-go

由虚拟时钟驱动的抢占式实时调度内核实验台。支持固定脚本一次跑完，
也支持在运行过程中从外部下发控制指令（中断、挂起、恢复、调优先级、动态加任务）。

## 虚拟时钟

时钟只在两种情况下推进：

1. 任务真正执行 `OpCompute`（每步 1 tick）；
2. 系统完全空闲时跳转到下一个待处理时刻（事件或指令的最早时刻）。

调度开销、下发指令、处理指令本身都**不推进**时钟。

## 运行期控制指令

通过 `Submit(tick, cmd)` 注册一条在虚拟时刻 `tick` 生效的指令；
可在 `Run` 运行中从其它 goroutine 并发调用（内部有锁，`-race` 干净）。

| 指令 | 语义 |
| --- | --- |
| `CmdInterrupt` | 中断：把**睡眠中**的任务立刻变为可运行，并取消其未到期的唤醒事件。等锁任务拒绝（`ErrCmdTaskLockWait`，锁归属不能悬空）。 |
| `CmdSuspend` | 挂起就绪/运行/阻塞中的任务。等锁任务挂起时退出锁等待队列、回滚 pc（恢复后重新执行加锁）并重算持锁者的继承关系；睡眠任务取消其唤醒事件。 |
| `CmdResume` | 恢复挂起任务：等锁挂起的回到就绪（重新加锁）；睡眠未到期的回到阻塞并重新注册唤醒；周期任务 job 间隙的回到阻塞等释放；其余回到就绪。 |
| `CmdSetPriority` | 修改任务基础优先级，立即重排其所在锁等待队列、沿等待链重算优先级继承；是否抢占由主循环按 `Config.Preemptive` 决定，关闭抢占时指令不能绕过。挂起中的任务允许改优先级。 |
| `CmdAddTask` | 在当前虚拟时刻加入新任务（不推进时钟）：非周期任务立即就绪；周期任务（`Period>0`）在当前时刻释放首个 job。重复任务 ID 拒绝（`ErrCmdDuplicateTask`）。 |

### 生效时刻与同 tick 顺序

- 指令在其注册 tick 生效：时钟到达该 tick 后、当次抢占检查与任务调度之前处理。
- 同一 tick 上**先处理内部事件**（周期释放 `evRelease`、睡眠唤醒 `evWakeup`，
  按既有的确定性全序），**再按提交顺序（seq）处理指令**。
- 同一场景重复运行得到完全一致的日志与结果，不丢事件也不重复处理。

### 处理结果

每条指令都产生一条 `CmdResult`（`CommandResults()` 获取），状态可区分：

- `CmdApplied`：已生效；
- `CmdNoop`：目标状态已满足（如对可运行任务发中断、重复挂起）；
- `CmdRejected`：被拒绝，`Err` 给出原因——
  `ErrCmdTaskUnknown`（任务不存在）、`ErrCmdTaskDone`（已结束）、
  `ErrCmdTaskSuspended` / `ErrCmdTaskNotSuspended`（挂起状态不匹配）、
  `ErrCmdTaskLockWait`（等锁任务不能中断唤醒）、
  `ErrCmdTaskDuplicateTask`（重复 ID）、`ErrCmdNoTask`（缺少任务对象）。

指向已结束或正被挂起任务的指令不会被悄悄吞掉，结果按 (tick, seq) 顺序完整记录。

## 与抢占 / 优先级继承的配合

- 指令处理发生在主循环的「事件处理之后、抢占检查之前」，因此调优先级、
  恢复、加任务的效果在**同一个 tick** 的调度决策中即可见。
- 抢占只由主循环的 `preemptIfNeeded` 触发，且受 `Config.Preemptive` 约束；
  指令只改变任务状态与优先级，不直接切换运行任务。
- 优先级继承沿锁等待链传递；运行期改优先级或挂起等锁任务后，
  等待队列顺序与继承关系立即重算，锁的归属与等待顺序不悬空。

## 本地验证

```sh
go test ./...          # 全部单测（含原有抢占/继承/超时回归）
go test -v ./...       # 查看每条用例覆盖的行为与结果日志
go test -race ./...    # 数据竞争检测（含并发下发指令用例）
```

运行期控制相关用例在 `sched/control_test.go`（`TestCmd*`），
覆盖：中断唤醒、等锁拒绝、挂起/恢复、等锁挂起后的继承重算、
运行期调优先级与抢占/非抢占、动态加（周期）任务、可区分拒绝、
同 tick 顺序、上量确定性（50 任务 × 500 指令重放一致）、并发下发。
